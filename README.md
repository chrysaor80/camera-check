# camera-check

카메라로 얼굴을 찍어 **심박수**를 뽑아 보는 시험용 웹 페이지입니다.
설치 없이 링크만 열면 됩니다.

| | 주소 |
|---|---|
| 얼굴 촬영 시험 | https://chrysaor80.github.io/camera-check/ |
| 카메라 성능만 확인 | https://chrysaor80.github.io/camera-check/check.html |

---

## 무엇을 하는 페이지인가

카페에 놓을 **놀이기구**를 만드는 중입니다. 얼굴을 잠깐 찍어서 값을 하나
보여주고 끝나는 물건입니다. 이 저장소는 그걸 만들면서 필요해진 **확인용
페이지 두 장**입니다.

### 1. 얼굴 촬영 시험 (`index.html`)

얼굴을 40초 찍어 심박수를 뽑고, 뽑아낸 맥박 파형을 함께 보여줍니다.
화면의 타원에 얼굴을 맞추고 움직이지 않으면 됩니다.

### 2. 카메라 성능만 확인 (`check.html`)

이 방식이 되려면 **카메라의 밝기를 한 값에 고정할 수 있어야** 합니다.
피부 밝기 변화가 0.1~1% 밖에 안 되는데, 카메라가 밝기를 자동으로 조절하면
그 변화를 카메라가 같이 지워버리기 때문입니다.

브라우저에도 규격상 노출 고정이 있지만 기기·브라우저·드라이버마다 실제로
되는지가 다릅니다. **된다고 적혀 있어도 값을 받고 무시하는 경우가 있어서**,
노출 시간을 바꿔가며 화면이 실제로 밝아졌다 어두워지는지를 재서 판정합니다.

실측 프레임 속도도 함께 잽니다. 설정값이 30 이어도 실제로 27 로 들어오면
심박수가 그 비율만큼 어긋납니다.

---

## 촬영본은 어디로도 가지 않습니다

- 인터넷으로 **전송하지 않습니다.** 서버가 없습니다
- 기기에 **저장하지 않습니다**
- 화면에서 보고 끝납니다. 페이지를 닫으면 남는 것이 없습니다

전부 브라우저 안에서만 돌아갑니다. GitHub Pages 는 이 파일을 내려주기만 합니다.

---

## 어떻게 값을 뽑는가

1. 이마와 양 볼에서 프레임마다 평균 RGB 를 읽습니다
2. 들어온 **시각 그대로** 균일 격자에 다시 얹습니다 (속도가 흔들려도 어긋나지 않게)
3. **POS**(Plane-Orthogonal-to-Skin) 로 맥박 성분을 분리합니다
4. 0.7~4.0Hz 대역통과 후 세 영역을 가중 합칩니다
5. **Welch PSD** 로 봉우리를 찾습니다. 20초 창을 10초씩 밀어 세 번 재고 중앙값을 씁니다

주파수 격자가 성기면 값이 뭉치므로 2048 로 제로패딩하고 3점 포물선 보간을
씁니다. 2배 주파수를 잘못 집으면 심박수가 두 배로 나오므로, 절반 주파수가
국소 최대이면서 충분히 셀 때만 그쪽을 택하는 방어를 넣었습니다.

파이썬 원본과 **같은 값·같은 절차**를 씁니다.

### 합성 신호로 확인한 값

정해진 주파수를 넣고 얼마나 되돌아오는지 본 것입니다.

| 넣은 값 | 나온 값 |
|---|---|
| 50 | 50.0 |
| 62 | 62.0 |
| 72 | 72.0 |
| 85 | 85.0 |
| 104 | 104.0 |
| 130 | 130.0 |

잡음을 키우면 오차가 커지는데, 그때는 화면에 **「신호가 약합니다」** 가
같이 뜹니다. 조용히 틀린 값을 내놓지 않게 한 것입니다.

**사람 얼굴은 합성 신호보다 훨씬 어렵습니다.** 위 값은 계산이 맞게 옮겨졌는지
확인한 것이지, 실제로 얼마나 맞는지를 말해주지 않습니다.

## 한계

- 얼굴 추적을 넣지 않았습니다. 화면의 타원에 맞추고 **움직이지 않아야** 합니다
- 밝기 고정이 안 되는 카메라에서는 값이 많이 흔들립니다
- 어두운 곳에서는 잘 안 됩니다
- 만드는 중인 화면입니다
